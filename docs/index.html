MC посчитан офлайн TS-движком (simulate) и вшит в страницу; WASM считает точное матожидание здесь, в браузере. Колонки MC — срезы одного непрерывного прогона 1 000 000 раундов (тот же seed) на 100k/200k/400k/800k/1M; σ падает как 1/√N. После «Посчитать» под каждым срезом — отклонение MC от точного WASM в п.п. RTP, цвет — по |Δ|/σ этого среза (зелёный <2σ, жёлтый <3σ, красный ≥3σ). Δ/σ = (WASM−MC@1M)/σMC@1M. Варианты с пометкой «подстройка RTP» перенастроены (масштаб выплат и/или ставка) так, чтобы точный RTP был ≈96%. Каскады и megaways параллелятся по стопам 1-го барабана на все потоки; лёгкие ядра идут по одному варианту на поток параллельно. WebGPU-колонки: для каждой вариации с барабанами 3×N и линиями/ways считается точное EV базовой игры (без фич, wild-замена, упрощённый оценщик) полным перебором всех комбинаций стопов — одна и та же задача на WASM (Rust, все потоки CPU, деление по стопам 1-го барабана) и на WebGPU compute shader (1 комбинация = 1 поток GPU, 64-битная целочисленная сумма). Время — без компиляции, с чтением результата. «WASM = GPU?» — совпадение сумм бит-в-бит. Megaways, Hold&Win и instant — «—» (не переносились). Без WebGPU считаются только WASM-колонки. старое сравнение TS vs WASM
